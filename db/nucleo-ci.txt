# Consumido por `db/roda-nucleo-ci.sh` (job `provas-sql` do ci.yml). Uma linha por
# script; `#` comenta; linha vazia ignorada. O runner EXIGE que todo caminho aqui
# exista e que o total executado bata com o total lido — lista vazia é ERRO, não
# "nada a fazer".
#
# ## Por que uma allowlist, e não `db/test-*.sh`
#
# São 289 provas (medido 2026-09-07). Um glob traria junto as que dependem de prod
# (`psql-ro`), de `deno`/`bun` ou de dados fora do repo — e a primeira vermelha por
# AMBIENTE ensinaria a tratar este job como flaky, que é como um gate morre. A lista
# cresce por adição deliberada: rode o candidato local, confirme que é autocontido
# (só initdb + SQL do próprio script), e acrescente na seção do eixo.
#
# ## A ordem dos eixos (parecer Codex, 2026-09-07)
#
# autorização > finitude monetária > atomicidade > concorrência. É a ordem de dano:
# um furo de autorização vale por todos os outros somados.

# Formato: <caminho> <mínimo de asserts> [falsificar=<n> | falsificar=fora-do-ci]
# O segundo campo é CONTRATO, não enfeite: o fechamento das provas é
# `[ "$FAIL" -eq 0 ]`, que **também aceita PASS=0** — uma prova truncada sai 0 e
# passaria. O runner exige que o nº de asserts EXECUTADOS seja ≥ este número.
# Subir asserts não quebra nada; encolher a prova reprova até alguém baixar o
# número aqui — e aí a perda de cobertura fica no diff, que é o ponto.
#
# O terceiro é OBRIGATÓRIO quando a prova tem modo `--falsificar` (o runner procura
# a flag no arquivo e reprova a linha que não declara). `falsificar=<n>` roda o modo
# aqui e exige ≥n sabotagens com o vermelho CERTO — mesma lógica de ratchet do 2º
# campo. `falsificar=fora-do-ci` é exceção declarada, com o motivo em comentário na
# MESMA linha; o runner a imprime em toda execução. Detalhe no cabeçalho do runner.
